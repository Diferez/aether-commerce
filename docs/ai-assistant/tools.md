# Aether AI Assistant Tools

Tools are deterministic wrappers around Aether Worker API.

Implementation lives in `apps/ai-assistant/app/tools.py`. The LangGraph flow selects the next tool, but product/variant resolution, cart item resolution, idempotency key construction and mutation execution are centralized in that tools module.

Tool outputs sanitize text from external services before returning data to the graph or storefront. Product names, descriptions, variant labels and cart item fields are treated as data, not instructions.

- `search_products`: calls `/api/v1/catalog/products` with strict filters.
- `get_product_details`: calls `/api/v1/catalog/products/:slug` or resolves by search.
- `get_product_variants`: reads variants from product details, filters by requested color/finish/size, excludes unavailable inventory and returns structured variant IDs, labels, SKU, attributes and stock state.
- `compare_products`: resolves exactly two products and fetches each product detail before building the comparison.
- `get_cart`: calls `/api/v1/cart/{cart_id}`.
- `add_to_cart`: calls `/api/v1/cart/{cart_id}/items`.
- `update_cart_item`: calls `PATCH /api/v1/cart/{cart_id}/items/{item_id}` with a quantity from 1 to 25.
- `remove_from_cart`: calls `DELETE /api/v1/cart/{cart_id}/items/{item_id}`.
- `clear_cart`: requires explicit user confirmation plus the internal `confirmation_token` generated by the graph, then removes items one by one until the Worker exposes a bulk clear endpoint.

The LLM never supplies price, stock, user identity or cart ownership.

`search_products` derives structured filters before calling the Aether catalog API. Supported filters include query text, category, minimum price, maximum price, color, size, brand terms, availability, sort order and result limit. Price filters are sent as integer cents to the Worker API through `minPrice` and `maxPrice`; the assistant does not filter prices in generated text. Similar-alternative requests can use the storefront `current_category` context, or resolve `current_product_slug` through product details to obtain a real category, so recommendations stay grounded in the page the customer is viewing.

Mutable operations write an audit event with request ID, thread ID, session hash, tool name, normalized arguments, target entity and idempotency key. Blocked mutable requests, such as missing cart authorization or missing confirmation to clear the cart, are also audited with `authorization_result=denied` and `execution_status=blocked`.

Cart tools require a signed cart token issued by the Worker API. If the token is missing, expired or bound to a different cart ID, the assistant asks the user to refresh/reopen the store instead of reading, opening checkout guidance from, or mutating the cart.

For `update_cart_item` and `remove_from_cart`, the assistant first reads the current cart and resolves the target item against product name, slug, product ID or variant ID. If the cart has multiple possible matches, it asks for clarification instead of choosing arbitrarily.

Before `add_to_cart`, the assistant fetches product details and resolves variants against requested color, finish, size, label, SKU or variant ID. If more than one available variant remains, it asks for clarification and does not mutate the cart. Availability questions such as "tienen talla 40?" use `get_product_variants` and do not create cart audit records because they are read-only.

References such as `el primero`, `el segundo`, `ese` and `that one` are resolved only against the most recent structured `products` list saved in the conversation. If no recent list exists, the assistant asks for clarification and does not call cart mutation tools.

Comparisons are read-only. The assistant compares only fields present in Aether product details, such as price, category, stock, rating and explicit attributes. If more than two candidates are found and no recent "first two" context exists, it asks which two products should be compared instead of choosing arbitrarily.
